# APP 调试行为规范（App Debug Rules）

本 skill 用于约束「调试 APP」时的行为边界，避免误操作导致状态丢失、数据异常、隐私泄露或影响用户正在进行的任务。
执行任何 APP 调试动作前，先逐条比对下方规则；命中禁止项时立即停止并说明原因。

---

## 一、硬性禁令（MUST NOT）

以下行为在任何情况下都**不允许**执行，除非用户在同一轮对话中给出明确、具体的授权。

### R001 禁止用截图验证 UI
- **截图不是验证 UI 的必要手段，也不是推荐手段**：截图只能看到「看起来像什么」，看不到控件的精确状态、坐标、属性。验证 UI 必须用系统级手段（见第二章）。
- 不得主动调用任何截屏、录屏、抓图能力（无论系统命令、快捷键还是工具），包括但不限于 Shizuku 截图、`adb screencap`、应用内 screenshot 接口等。
- **禁止**对截图做像素分析来「验证」图标颜色、布局等——这类信息用 `dumpsys window` / `uiautomator dump` 能拿到更精确的系统级事实。
- **禁止**因为「看不到截图」就认为验证未完成或任务阻塞——系统级手段拿到的信息往往比截图更可靠。
- 仅在用户**明确要求**查看当前画面、且说明用途时才可执行；执行后需告知用户，并**立即删除**截图文件，不留存。
- 理由：截图会原样落盘并进入上下文，可能泄露隐私（WiFi 明文密码、聊天内容、账号、文件路径、已装应用、通知内容等）；且像素级「看图」判断远不如系统属性精确、可回溯。

### R002 禁止擅自跳转到其他 APP / 页面
- 不得主动切换、拉起、唤起其他应用，也不得在当前 APP 内随意跳转到无关页面。
- 跳转目标、时机必须由用户明确指定。
- 理由：随意跳转会打断用户操作流、丢失现场，或触发非预期的业务逻辑。

### R003 禁止擅自结束 / 杀掉进程
- 不得主动 kill、force-stop、关闭正在运行的 APP 进程或相关服务。
- 即便调试需要重启，也应先征求用户同意，并说明影响范围。
- 理由：强制结束进程可能造成数据未落盘、状态丢失或后续功能异常。

### R004 禁止抢占设备 / 模拟器前台
- 不得主动把目标 APP 拉到前台、聚焦窗口或抢占正在使用的设备焦点。
- 调试应尽量在后台完成（读日志、查状态、跑命令），交互验证交由用户在实机操作。
- 理由：抢前台会打断用户正在做的事，也可能让自动化验证误触到错误界面。

## 二、正确的 UI 验证手段（按可靠性从高到低）

验证 UI / 界面状态**必须**用以下系统级手段，不要用截图。它们拿到的是系统层面的事实，不需要看像素就能确认。

### 1. `dumpsys window` — 系统级窗口状态
```bash
adb shell dumpsys window <package>
```
能看：前台 Activity、窗口属性、状态栏标志（`vsysui` / `apr`）、系统 UI 可见性标志。

状态栏图标颜色验证（无需看像素）：
- `vsysui=LIGHT_STATUS_BAR` → `SYSTEM_UI_FLAG_LIGHT_STATUS_BAR` 已设置 → **黑图标**（浅色背景用）
- `vsysui=DARK_STATUS_BAR` 或无 LIGHT 标志 → **白图标**（深色背景用）

### 2. `uiautomator dump` — 完整控件树
```bash
adb shell uiautomator dump
adb shell cat /sdcard/window_dump.xml
```
能看：每个控件的文字、坐标、`resource-id`、可见性、状态。比截图更精确，能确认「页面上有什么文字、按钮是否可点击、控件是否可见」。

### 3. ControlProvider / 应用内调试接口 — 应用内方法调用
```bash
adb shell content call --uri content://<package>.control --method state
adb shell content call --uri content://<package>.control --method navigate --arg <route>
```
能看：应用内状态（VM 状态、版本号、路由等）、执行导航等操作并确认结果。直接验证应用逻辑，不依赖视觉。
（具体 URI / method 以目标 APP 实际暴露的调试接口为准。）

### 4. `logcat` — 运行时日志
```bash
adb logcat -s <tag>
```
能看：运行时错误、状态变化、崩溃日志。**辅助验证**，不能单独作为 UI 验证依据。
（注意：production build 的 logd 对 shell 可能限制 main 缓冲读取，抓不到应用日志时改用结果文件 / dumpsys 佐证，不要反复重试。）

### 其它取证原则
- **截图用完即清理**：万一按 R001 例外截了图，调试结束主动询问是否删除；含敏感数据的截图用完立刻删，不堆积在设备或工作目录，不得在 `/tmp`、`/usr/share/tawc/` 等目录残留。
- 任何有副作用的操作（启动、点击、输入、滑动、清缓存等）执行前，先说明「将要做什么 + 影响」。
- 优先采用只读、无损的方式定位问题（查看日志、读配置、检查状态），再考虑有副作用的手段。
- 调试结束后，尽量将 APP 恢复到调试前的界面与状态。

## 三、构建 / 安装 / 验证（环境相关）

- **资源受限环境编译**：Gradle / Kotlin daemon 可能因 GC 崩溃（报 `daemon has terminated unexpectedly ... GC`），加 `-XX:+UseSerialGC` 并用 `--no-daemon` 重试。
- **production build 无注入权限**：release/production 包没有 `INJECT_EVENTS`，`input tap/swipe` 会被拒——交互验证只能靠用户实机，不要反复重试注入或误判为 bug。
- **装机优先 `-r` 覆盖安装**：`adb install -r` 保留数据；需要清数据时先说明影响再操作。
- 编译 variant / flavor 名不确定时，先 `gradlew :app:tasks --all` 查实际 task，不要凭猜测拼任务名。

```markdown

- 触发场景：什么情况下适用本规则。
```

## 1. 修复首页闪退（根因定位）+ 崩溃报告页（防闪退）+ Shizuku 合并状态卡

### 1.1 首页「打开就闪退」根因定位与修复（关键）
- 现象：打开 App 即闪退，且 logcat 缓冲被排空抓不到栈。
- 突破：发现 `CrashLogger` 早已把崩溃落盘到 `files/crash/crash-<ts>.txt`，`adb shell run-as com.codetool.app cat files/crash/<最新>` 直接读到真实栈（绕开 logcat）。
- 根因（崩溃文件确证）：本轮新加的 CPU 监测读 `/proc/stat`，在 **Xiaomi M511CD（HyperOS / Android 17 API 37）** 上 `EACCES (Permission denied)`——该 ROM 限制 `/proc/stat` 应用访问。`HomeFragment.readCpu()` 未被 runCatching 兜住，异常经协程默认处理器崩掉 App。
- 修复：**整体移除 CPU + 运行内存监测**（feature 与该 ROM 不兼容）。
  - `HomeFragment.kt`：删 `cpuText/cpuIcon/memText/memIcon` 字段、findViewById、初始 tint、`startResourceMonitor/readCpu/cpuPercent/memLabel/formatKb/lastCpu`。
  - `fragment_home.xml`：删 CPU/内存两行。
  - 删除 `drawable/ic_cpu.xml` / `ic_ram.xml`。
- 验证：正常冷启动连续 3/3 存活（此前必崩）。

### 1.2 崩溃报告页（防闪退：出错显示日志页而非无痕闪退）
- `CrashReportActivity.kt` + `activity_crash_report.xml`：展示完整堆栈 + 「复制日志」「重启应用」。
- `CrashLogger`：崩溃时写文件后 `startActivity(CrashReportActivity, NEW_TASK|CLEAR_TASK)`，不再调 defaultHandler（避免系统「已停止」弹窗和崩溃页打架），延迟 200ms 再 killProcess。
- Manifest：`CrashReportActivity` 跑独立 `android:process=":crash"`——主进程崩溃退出后崩溃页仍能显示。
- `CrashLogger.lastCrashText()` 改为从 `files/crash/` 读时间戳最新文件（原读内存 lastCrashFile 在独立进程里为空，会显示「未读到详情」）。
- 自检钩子：`MainActivity` 加 `codetool_debug_crash` extra，**仅 FLAG_DEBUGGABLE 构建 + 显式 extra** 才抛异常，正常使用永不命中；`adb shell am start ... --ez codetool_debug_crash true` 可验证。
- 验证：触发自检崩溃 → 跳崩溃页显示完整真实堆栈（设备/线程/版本/RuntimeException/调用栈），不闪退。

### 备注
- `/proc/stat`、`/proc/meminfo` 在部分锁定 ROM（HyperOS 等）对应用 EACCES，做系统资源监测需容错或改用其他 API；本次直接移除该 feature。

## 3. 内置 Shizuku 调试桥：让 AI 模型以 shell 身份调试 App（替代无线调试）

### 3.1 背景与方案
- 需求：让集成在容器里的 AI 模型（mimo/opencode）能直接调试本 App——截屏、导出界面控件树、跑 dumpsys/logcat，比让用户手动连无线调试截图方便。
- 复用现有「文件桥」三段式（照抄 BrowserBridge 范式）：容器脚本写 `share/shizuku/requests/<id>.json` → App 侧 FileObserver 收到 → 用 Shizuku user-service 执行 → 写 `responses/<id>.json` 供脚本轮询。无需新造 IPC、无需 root。
- Shizuku 让 App 以 shell（adb，uid 2000）身份执行，权限等同 adb，能做截屏/dumpsys/uiautomator，**不需要连 adb**。

### 3.2 改动文件
- `app/src/main/aidl/com/codetool/app/shizuku/IShizukuUserService.aidl`：新增 AIDL 接口，`String exec(String cmd)`。
- `app/src/main/java/com/codetool/app/shizuku/ShizukuUserService.kt`：user-service 实现，经 `sh -c` 执行命令（外部 timeout 30s 兜底），回收 stdout+stderr，返回 `exit=N\n<输出>`。
- `app/src/main/java/com/codetool/app/shizuku/ShizukuBridge.kt`：照抄 BrowserBridge 的 FileObserver 桥。监听 `share/shizuku/requests`，后台单线程 executor 执行（bind/exec 阻塞，避免卡主线程）；未授权时明确返回「去首页点 Shizuku 行申请授权」。bind 用 `Shizuku.bindUserService(args, conn)`，unbind 用 `unbindUserService(args, conn, true)`（存下 args 字段）。
- `app/src/main/java/com/codetool/app/CodeToolApp.kt`：onCreate 启动 `ShizukuBridge.start(this)`，桥常驻（随 App 进程，不依赖 GUI 合成器）。
- `app/src/main/java/com/codetool/app/runtime/TawcrootRuntime.kt`：ensureGuiBridge 建 `share/shizuku` 挂载点 + 注入 `codetool-shizuku` CLI 脚本（单一来源 assets）。
- `app/src/main/assets/scripts/codetool-shizuku.sh`：容器内 CLI，`status` / `exec '<命令>'` / `screenshot [路径]` / `uidump [路径]`。
- `app/src/main/assets/scripts/codetool-mcp.py`：`bridge_request` 加 `bridge` 参数支持 shizuku 桥目录；新增 4 个 MCP 工具：`shizuku_status` / `shizuku_exec` / `shizuku_screenshot` / `shizuku_ui_dump`。
- `app/src/main/java/com/codetool/app/ai/SkillManager.kt`：重构 ensureBuiltin 支持多内置 skill（`ensureOne(id,desc,body,marker)`）；新增内置 skill `codetool-shizuku`，教模型用它调试 App（含典型流程与常用 dumpsys/logcat 命令）。
- `app/build.gradle.kts`：启用 `aidl = true`；`buildToolsVersion = "37.0.0"`（34/36 的 aidl 是 x86_64/脚本，本机 aarch64 跑不了，37.0.0 是 aarch64 原生二进制）。

### 3.3 关键实现
- **AIDL 编译坑**：build-tools 34.0.0 的 `aidl` 是 x86_64（e_machine=0x3E），36.0.0 是脚本，只有 37.0.0 是 aarch64（0xB7）。显式 `buildToolsVersion = "37.0.0"` 才能编译 AIDL。
- **Shizuku API 13.1.5**：无 `newProcess`，走 user-service。`UserServiceArgs` 只有 `daemon/tag/version/debuggable/processNameSuffix`（无 processCount）。`bindUserService(args, conn)` 两参数；`unbindUserService(args, conn, boolean)` 三参数需存 args。
- **截图/UI dump 路径**：写到 `data/data/com.codetool.app/share/shizuku/`（shell 可写，App dataDir），容器经 bind mount 在 `/usr/share/tawc/shizuku/` 直接读。

## 补充 5：shizuku 脚本多行 / 引号 / 管道 / 非零退出码

### 背景 / 问题
- `codetool-shizuku.sh` 早期用 `sh -c` 拼命令，含引号、管道、多行、非零退出码时
  传给 bridge 的结果会错（JSON 只包 stdout，退出码丢失，stdout 内嵌换行被转义）。

### 改动
- 改为 Python3 单层编解码：参数以 JSON 数组传给 python3，bridge 返回的 JSON
  再 decode 后 `print()` 还原（换行恢复成真换行）。
- 非零退出码：bridge 响应里的 exit_code 透传，脚本最后 `exit` 该值（失败不静默）。
- 多行命令：按行拆分逐行喂给 bridge，最后汇总；行内引号/管道原样传。

### 验证
- 脚本已更新（`/usr/local/bin/codetool-shizuku` 由 ensureGuiBridge 注入），
  **待验证**：容器内跑 `codetool-shizuku exec 'echo a | tr a b'`、多行 here-doc、
  `exit 3` 这类命令，确认 stdout/退出码正确。

### 补充：定位到浏览器安装中断的真正根因（snapd + dpkg --configure -a）
用户贴出完整日志：第 165 行 `dpkg --configure -a` 遇到损坏的 snapd 报
`unable to set CAP_SETFCAP effective capability: Operation not permitted`（proot 容器设不了
capability，snapd post-install 必失败），返回 1 → 整段前置中断，走不到 snapd 移除、更走不到 Firefox。

修复：`dpkg --configure -a` 加 `|| true` 容错（前置段 PackagesFragment.browserPrereq、
桌面图标 DesktopApps.BROWSER_INSTALL 两处），让它活到 snapd 移除。移除后 apt 装 firefox/chrome 不再被 snapd 卡住。

### 补充 2：apt-get update 因失效第三方源中断安装 → 改容错
snapd 过了之后 Firefox 本体仍失败。根因：`( set -e )` 块里 `apt-get update && apt-get install`，
只要任一第三方源拉取失败 update 就返回非零 → set -e 中断，firefox 装不上。用户 apt-get update 出现
两个 chrome 源（chrome/deb + chrome-stable/deb），疑似残留失效源。

修复：Firefox/Chrome（包管理 + 桌面图标）的 `apt-get update && apt-get install` 改为
`apt-get update || echo '[WARN]...'` + `apt-get install`，update 部分源失败不再一票否决，
只要目标源（mozilla / google-chrome）正常就能装上。已编译装机。

### 补充 3：真正根因——Firefox 把 snapd 当依赖拉回来重装
用户贴出完整日志终于定位：`apt-get install firefox` 输出 `The following additional packages will be installed: snapd`，
apt 把 snapd 又装回来，snapd post-install 在 proot 下 CAP_SETFCAP 失败 → dpkg 返回 1 → 整个安装失败。
之前只是「装前」清 snapd，但 Firefox 本体会重新拉回，治标不治本。

修复（PackagesFragment）：
- `browserPrereq`：移除 snapd 后加 `echo 'snapd hold' | dpkg --set-selections` 锁死，apt 不敢再装它；
  移除补 `--purge` + `|| true`。
- Firefox 安装：`apt-get install -y --no-install-recommends firefox`，跳过 snapd 等 Recommends
  （Depends 照装）。若 snapd 是硬 Depends 会报「firefox depends on snapd but on hold」，届时需另找非 snap 的 deb。

待验证：实机再点「安装 Firefox」看是否装上 / 或报 snapd 硬依赖。

### 补充 4：snapd 是 Mozilla Firefox 硬依赖 → 改 tarball 直装绕开 apt
`--no-install-recommends` 无效，日志显示 `The following NEW packages will be installed: firefox snapd`——snapd 是
Mozilla apt 包的硬 Depends（Recommends 才会被 --no-install-recommends 跳过）。`dpkg --set-selections` 的 hold 对
已卸载的包也不生效。结论：走 apt 装 Mozilla Firefox 在 proot 容器里必然被 snapd 炸。

修复：Firefox 改从 Mozilla 官方 ftp 下 tarball 直装，完全不碰 apt/snapd：
- wget 下 `https://ftp.mozilla.org/pub/firefox/releases/146.0/linux-aarch64/en-US/firefox-146.0.tar.xz`
- `tar -xJf` 解压到 /opt/firefox，`ln -sf /opt/firefox/firefox /usr/local/bin/firefox`
- 校验 /opt/firefox/firefox 可执行；自检 `firefox --version`。
版本号写死 146.0，若 Mozilla 归档无此版本需改指向最新。

待验证：实机再点「安装 Firefox」看是否装上 / 下载是否 404（版本号）。

### 验证结果（补充 4）
实机再点「安装 Firefox」：tarball 下载 65MB 成功、解压、软链，`firefox --version` 返回
`Mozilla Firefox 146.0`，[OK]。版本号 146.0 在 Mozilla 归档有效。GUI 内启动待用户在合成器里确认。

## 2. 修复 Firefox 安装后包管理仍显示「未安装」
- 根因：`DesktopApps.firefoxInstalled()` 查 `apps` 里 `id=="firefox"` 的条目，但列表里没有
  firefox 条目（桌面浏览器用 chrome），`firstOrNull` 恒 null → `?: false` → 恒 false。
- 修复：改 `resolveBinary(context, "firefox")`，直接解析 `/usr/local/bin/firefox` 软链
  （tarball 安装建的），SEARCH_DIRS 覆盖 usr/local/bin。
- adb 实机验证：容器 `ubuntu-noble-aarch64/usr/local/bin/firefox` 软链存在；
  装新 APK 后包管理页显示「Firefox 已安装 · 点此重装」。
- 待办：v2.0.3 已发布的 APK 仍带此 bug，需发 2.0.4 修复。

### 补充：Firefox 重装按钮去掉多余 apt 前置段
Firefox 走 tarball 直装，原本还拼了 browserPrereq（apt + snapd 清理），对 tarball 无意义且误导。
去掉后重装纯净：只下载解压软链，不碰 apt/snapd。Chrome 重装则因官方 deb 不依赖 snapd，本就安全。
结论：两个浏览器重装都不会再复现 snapd 崩溃。无法从 adb 直接跑容器 apt 验证（需 tawcroot 运行时），
依据脚本逻辑 + 已验证二进制状态判断。

## 8. apt/dpkg 锁被占 → 加等锁 + 修误报成功
- 现象：残留 apt-get（pid 14743）占 dpkg 锁，「更新依赖」apt-get install 报 Could not get lock 失败，
  但脚本末尾仍无条件 echo [OK] 常用组件就绪（误报）；gnupg 没装上 → 再装 Chrome 报缺 gpg。
- 修：PackagesFragment 加 aptWaitLock（wait_apt_lock 函数，pgrep 检测 apt-get/apt/dpkg，最多等 120 秒），
  所有走 apt 的脚本前置调用（更新依赖/MiMo/opencode/APM/ADB/浏览器前置段）；星火自带重试不重复加。
- 「更新依赖」改为 if apt-get install; then [OK] else [ERROR] fi，不再无条件报成功。
- 构建 + 装机通过。apt 锁是容器全局文件锁，多标签页并发跑 apt 照样冲突，等锁使其排队而非失败。

## 14. 终端执行脚本不再回显源码 + APK 图标换版 + 桌面去重收尾
- 背景：包管理里「更新依赖」等按钮执行后，终端显示的是整段脚本源码（`echo '...'`、`if/then`、`>` 续行提示符），
  而不是运行结果。根因是 `runInTerminal` 直接把多行脚本文本写进交互式 PTY，终端会把输入也回显。
- 修：`TerminalFragment` 新增 `runInlineScript(context, name, script)`：脚本先写入 cacheDir 临时文件，
  再复用已有 `runScript`（复制进容器 `/root/.codetool-scripts/` 后 `sh <路径>`），终端只显示一行命令 + 真正输出。
  `runInTerminal` 改为调用它；写文件失败时兜底退回 `sendCommand`。
- 同步排查其它多行 sendCommand：
  - `PackagesFragment` 启动星火商店（Wayland 环境变量段）→ 改 `runInlineScript`。
  - `AiModelsFragment` 「修复 PATH」（FIX_PATH_SCRIPT）→ 改 `runInlineScript`（脚本为 POSIX + heredoc，sh 可执行）。
  - `gui/DesktopApps.runScript` 是 `exec bash -lc` 直跑进程，不进 PTY，无源码回显，无需改。
  - `FilesFragment` 的 `cd '<路径>'` 是单行，保留。
- `desktopApps` 重复 Google 图标收尾：`discoverInstalled` 去重同时比对 curated 的 id 与 cmd 二进制名，
  并加前缀兜底（google-chrome-stable / -beta 变体），修 id=chrome 与 .desktop 里 google-chrome-stable 不匹配导致的重复项。
- `ic_apk.xml` 换成「文档 + 安卓机器人」图形（用户提供路径）；颜色仍由 `item_file.xml` 的 `app:tint="?attr/colorPrimary"` 控制，跟随主题。
